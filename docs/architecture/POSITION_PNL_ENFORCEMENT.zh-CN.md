# 持仓盈利率强制平仓（代码执行）

**语言:** [English](POSITION_PNL_ENFORCEMENT.md) | [中文](POSITION_PNL_ENFORCEMENT.zh-CN.md)

本文描述**实盘自动交易员**（非网格策略）如何根据「相对保证金的盈亏百分比」自动减仓或平仓。实现以当前代码为准。

**核心实现：** `trader/auto_trader_pnl_enforce.go`、`trader/auto_trader_loop.go`（`buildTradingContext`）

---

## 1. 这是什么

系统在从交易所拉取最新持仓后，用**保证金收益率**（下文简称 **Margin 盈亏%**）与策略里配置的风控阈值比较。命中规则时**不等待 AI**，直接下发平仓/减仓订单；日志与决策理由中带 `[CODE ENFORCED PnL]` 标记。

这与以下情况不同：

| 类型 | 谁执行 | 说明 |
|------|--------|------|
| **本文：盈利率强制** | 后端代码 | 按 Margin 盈亏% 与峰值回撤等规则 |
| **AI 决策平仓** | 模型输出 `close_long` / `close_short` | 每轮扫描周期内的正常决策 |
| **用户一键平仓** | `POST /api/traders/:id/close-position` | 前端/API 手动全平 |
| **交易所爆仓** | 交易所 | 触及强平价由交易所平仓；本系统不模拟、不按强平价主动下单 |
| **回测强平** | `backtest` 模块 | 仅回测环境按模拟强平价检查 |

**网格交易策略**不走这套盈利率强制逻辑。

---

## 2. 什么时候检查

检查发生在：**持仓快照刚算完、且交易员处于运行中** 时。没有单独的「每分钟后台任务」。

### 2.1 主要路径：AI 扫描周期

1. 交易员启动后**立即**跑一轮周期；
2. 之后按 Agent 配置的 **扫描间隔**（常见 3 分钟，以界面/配置为准）重复。

每轮周期内顺序大致为：

```
拉余额与持仓 → 计算 Margin 盈亏% → 【盈利率强制检查，可能下单】 → 若已平仓则刷新上下文 → AI 决策
```

对应代码：`runCycle()` → `buildTradingContext()` → `onPositionsUpdated()`。

### 2.2 辅助路径：账户接口

以下调用在拉完持仓后也会触发同一套检查：

- `GET /api/account`（仪表盘默认约 **每 5 秒** 轮询一次）
- 内部 `GetAccountInfo()` / `GetTraderSnapshot()`（助手查账、竞赛页等）

**不会触发**的检查：

- 仅 `GET /api/positions`（只返回列表，不跑强制逻辑）
- 交易员已停止
- 网格策略模式

### 2.3 防重复

同一持仓快照在 **800 毫秒内**重复请求会被跳过（避免连下两单）。快照指纹包含：标的、方向、数量、标记价、Margin 盈亏%。

## 3. 判断用什么数据

### 3.1 交易所 API（主来源）

以 OKX 为例（`trader/okx/trader_positions.go`），每次从 REST 读取：

| 用途 | 来源 |
|------|------|
| 持仓数量 | 合约张数 × 合约面值 |
| 标记价 | 交易所 `markPx` |
| 未实现盈亏（USDT） | 交易所 `upl` |
| 杠杆倍数 | 交易所 `lever` |
| 强平价 | 交易所 `liqPx`（仅展示/给 AI，**不参与**本强制逻辑） |

余额：`GetBalance()`（如 OKX 的 `totalEq`、可用 USDT、`upl` 等）。

### 3.2 Margin 盈亏% 计算公式

```
保证金占用 ≈ 持仓数量 × 标记价 ÷ 杠杆倍数
Margin 盈亏% = 未实现盈亏 ÷ 保证金占用 × 100
```

**说明：** 当前实现用上述公式估算保证金，**未**直接使用 OKX 返回的 `margin` 字段。与交易所 App 展示的收益率可能存在小幅差异。

### 3.3 峰值盈利（用于「从高点回撤」）

- 内存缓存 `peakPnLCache`，每次采样更新；
- 数据库 `trader_positions` 表同步峰值（重启后可恢复）；
- 判断时取 `max(缓存峰值, 当前 Margin 盈亏%)`。

全平或减仓比例 ≥100% 后会清除该仓的峰值缓存与强制档位记录。

### 3.4 策略阈值

来自当前绑定策略的 **风控配置**（数据库存储）。配置为 0 或未填时使用产品默认值（见下表）。

## 4. 会强制执行的规则（优先级从高到低）

同一仓位每轮只执行**命中优先级最高的一条**。

| 优先级 | 规则名称 | 默认条件 | 动作 |
|--------|----------|----------|------|
| 1 | 亏损止损 | Margin 盈亏% ≤ **-5%** | 全部平仓 |
| 2 | 峰值回撤 | 历史峰值 ≥ **10%**，且从峰值回落 ≥ **4** 个百分点 | 全部平仓 |
| 3 | 锁盈二档 | Margin 盈亏% ≥ **12%**，且该仓尚未执行过二档 | 减仓 **40%**（代码固定比例） |
| 4 | 锁盈一档 | Margin 盈亏% ≥ **8%**，且该仓尚未执行过一档 | 减仓 **30%**（可在策略中调整比例） |

策略里可改的数值（界面「风控」相关项，中文理解即可）：

- **亏损止损线**（默认 -5%）
- **锁盈一档盈利线**（默认 8%）与 **一档减仓比例**（默认 30%）
- **锁盈二档盈利线**（默认 12%）；二档减仓比例在代码中固定为 40%
- **峰值回撤门槛**（默认峰值至少 10% 才启用）
- **峰值回撤幅度**（默认从峰值回落 4 个百分点）

### 仅写在提示词里、代码不会自动执行

- **「盈利较高且出现反转再平仓」**（策略里常见约 10% 的保护利润线）：只引导 AI，后端不自动下单。
- 开仓时的 **止损价 / 止盈价** 校验与挂单：见策略模块文档中的「开仓保护」；与持仓盈利率强制是两套机制。

---

## 5. 执行方式

1. 构造 `close_long` / `close_short` 决策，`CloseRatio`：0 表示全平；0~1 表示按**交易所实时持仓数量**的比例减仓。
2. 平仓前再次 `GetPositions()`，数量以交易所为准。
3. 记录价优先用持仓标记价（带 `[CODE ENFORCED PnL]` 时走快速路径，少打一次行情接口）。
4. AI 周期内触发的动作写入当轮决策日志；仅因拉账户触发的会单独 `saveDecision` 一条记录。

## 6. 配置与占位示例

在 Web **策略 → 风控** 中调整阈值即可，无需在文档中填写真实密钥或账户信息。

示例（占位，非真实配置）：

```json
{
  "risk_control": {
    "stop_loss_pnl_pct": -5,
    "lock_profit_pnl_pct": 8,
    "lock_profit_reduce_ratio": 0.3,
    "lock_profit_second_pnl_pct": 12,
    "peak_min_for_pullback": 10,
    "peak_pullback_pts": 4
  }
}
```

交易所凭证在界面填写，例如：

- API Key：你的 API Key
- Secret Key：你的 Secret Key  
- Passphrase（OKX）：你的 Passphrase  

切勿将真实密钥写入文档、截图或聊天记录。

## 8. 常见问题

**Q：文档写「每分钟监控」是否准确？**  
A：不准确。实际频率 = **扫描间隔** + **仪表盘拉账户频率**（约 5 秒），且无持仓变化时可能被 800ms 去重跳过。

**Q：为什么锁盈二档和提示词写的 30%~50% 不一致？**  
A：代码中二档固定减仓 40%；一档比例来自策略配置（默认 30%）。

**Q：Agent 停了还会强制平仓吗？**  
A：不会。`isRunning == false` 时直接跳过。
